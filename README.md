# LifeLink

> A blood donation companion app built with Flutter + Firebase — designed for donors in Metro Manila.

LifeLink helps you track your eligibility, find nearby donation centers, book appointments, and respond to urgent blood shortage alerts. All donor data, bookings, notifications, and blood supply levels are persisted in **Cloud Firestore** with real-time updates.

---

## Features

### 🔐 Authentication
- Email/password sign-up and sign-in via Firebase Auth
- Blood type selection during registration
- Forgot password / email reset flow
- Automatic auth-gate routing (login ↔ app shell)

### 🏠 Home Dashboard
- Personalized greeting with blood type badge (live from Firestore)
- Eligibility card showing days until next donation
- Blood supply grid for all 8 blood types — **live Firestore data**, editable by admin
- Personal impact stats — donations, lives helped, blood given
- Quick-access list of nearby donation centers (live from Firestore)

### Pulse Alert
- Full-screen urgent shortage overlay
- Shows blood type needed, supply percentage, and nearest open centers
- One-tap action to jump straight to booking

### 🔔 Alerts
- Real-time notification feed per user from Firestore
- Grouped New / Earlier with unread badge count
- Mark all as read — persisted to Firestore (batch write)
- Seed notifications created automatically on registration

### Booking Wizard
A 4-step appointment flow:
1. Pick a date and time slot
2. Health screener questionnaire
3. Review your appointment details
4. Confirmation — **appointment saved to Firestore**

### Map
- Interactive OpenStreetMap powered by `flutter_map`
- Donation center pins with slot-availability indicators (live from Firestore)
- Search by name or address, filter by "Slots open" or "Nearby"
- Bottom sheet with center cards and direct booking CTA

### 👤 Profile
- Collapsing header with avatar, blood type (from Firestore), and donation streak
- Three tabs: **History · Challenges · Badges**
- History loaded from `users/{uid}/donationHistory` sub-collection
- Sign out button with confirmation dialog

## 🗄️ Firestore Schema

```
users/{uid}
  ├── name, email, bloodType
  ├── donationsTotal, livesHelped, bloodGivenL
  ├── streakCount, daysUntilEligible, nextEligibleDate
  ├── challenges[]  (array of challenge objects)
  ├── badges[]      (array of badge objects)
  └── donationHistory/  ← sub-collection
        └── {docId}: date, center, type, volumeL

appointments/{docId}
  ├── userId, centerId, centerName, centerAddress
  ├── date, time, status
  └── createdAt

notifications/{uid}/items/{docId}
  ├── type, title, body
  ├── isRead, hasAction, actionLabel
  └── createdAt

centers/{docId}          ← admin-managed, seeded once on first run
  ├── name, address, hours, distanceKm
  ├── slotStatus (open | limited | full)
  └── lat, lng

bloodSupply/{type}       ← admin-managed, seeded once on first run
  └── type, percentage
```

## Getting Started

### Prerequisites
- Flutter SDK 3.12+ · Dart SDK 3.12+
- A Firebase project (free Spark plan is fine)

### 1 — Install the FlutterFire CLI

```bash
dart pub global activate flutterfire_cli
firebase login
```

### 2 — Configure Firebase

From the project root:

```bash
flutterfire configure
```

Follow the prompts to select or create your Firebase project and pick the target platforms (Android, iOS, Web, Windows). The CLI will:
- Overwrite `lib/firebase_options.dart` with real values
- Place `google-services.json` in `android/app/`
- Place `GoogleService-Info.plist` in `ios/Runner/`

### 3 — Enable Firebase services

In the [Firebase Console](https://console.firebase.google.com):

1. **Authentication** → Sign-in method → Enable **Email/Password**
2. **Firestore Database** → Create database → Start in **test mode** (lock down rules before going to production)

### 4 — Run

```bash
flutter pub get
flutter run
```

On first launch, the app auto-seeds donation centers and blood supply levels into Firestore. You can edit those documents directly in the Firebase Console — the app picks up changes in real time.

## 🔒 Firestore Security Rules (production)

Replace the default test rules with these before going live:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Users can only read/write their own profile
    match /users/{uid} {
      allow read, write: if request.auth != null && request.auth.uid == uid;

      match /donationHistory/{doc} {
        allow read, write: if request.auth != null && request.auth.uid == uid;
      }
    }

    // Appointments: owner read/create only
    match /appointments/{docId} {
      allow create: if request.auth != null
                    && request.resource.data.userId == request.auth.uid;
      allow read: if request.auth != null
                  && resource.data.userId == request.auth.uid;
    }

    // Notifications: owner read/write
    match /notifications/{uid}/items/{docId} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }

    // Centers + blood supply: public read, no client writes
    match /centers/{docId} {
      allow read: if request.auth != null;
    }
    match /bloodSupply/{docId} {
      allow read: if request.auth != null;
    }
  }
}
```
